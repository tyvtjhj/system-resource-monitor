## 2. `API_BASE` 逻辑（T3.1）

```javascript
const API_BASE = new URLSearchParams(location.search).get('api')
  || (location.protocol === 'file:' ? 'http://127.0.0.1:5678' : location.origin);
```

- 页面由本服务提供（含反向代理、非 5678 端口、HTTPS 终止在代理）时，请求自动指向当前 `origin`，不再写死 `http://host:port`。
- `?api=http://host:port` 可显式指定后端（远程开发 / 分离部署）。
- `file://` 打开页面时回退到本机默认 5678。
- `?token=` 读取、`X-Monitor-Token` 头、`cache: 'no-store'` 均保持不变。

## 3. 第二轮评审修复（2 项）

| 评审问题 | 修复 | 验证 |

## 4. 能力降级（T3.2）

| 条件 | 行为 |
|---|---|
| `capabilities.gpu_integrated === false` | iGPU 卡片：gauge 归零、徽标 `--%`、信息行「当前平台不可用」 |
| `capabilities.gpu_nvidia === false` | GPU 卡片：徽标 `--%`、信息行「当前平台不可用」；主页面 GPU 卡片取消点击（`onclick` 清空、cursor 恢复默认、title 提示），`openGpuSidebar()` 入口同时加守卫 |
| `capabilities` 缺失（旧后端 / 加载前） | 视为「支持」，保持既有行为不变（兼容 T2 之前的后端） |
| `temperature.cpu.source` 缺失或未知 | `cpuTempLabel` 显示 `--`（原来回退成 `CPU`），`title` 仍给出「来源未知」提示 |

> 能力表语义沿用 T2：`capabilities` 表示**平台支持什么**，不代表设备一定存在；设备缺失仍走原有「未检测到核显 / GPU 无数据」分支。
