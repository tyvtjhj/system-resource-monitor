## 2. 对审查意见的修复

| 审查问题 | 修复 |
|---|---|
| **依赖安装入口未锁定** | `requirements.txt` / `requirements-dev.txt` 现为 `uv pip compile --universal --python-version 3.10` 生成的**确定性锁文件**：12 个运行时包全部 pin 版本，`wmi`/`pywin32` 带 `sys_platform == 'win32'`、`pynvml`/`nvidia-ml-py` 带 `sys_platform != 'darwin'` marker。`uv pip install -r requirements.txt` 审计通过、`uv pip check` 无冲突。 |
| **启动入口绕过 `.venv`** | `run.bat` / `run-admin.bat` / `run.sh` 均优先使用项目 `.venv`；实测 `run.bat` 输出 `[run] python: .venv\Scripts\python.exe` 并成功启动服务（见 §3.4）。 |
| **`requirements.in` 编码风险** | `.in` 文件注释改为**纯 ASCII**。pip / pip-tools 用系统 locale 解码 requirements 文件（中文 Windows 为 GBK），UTF-8 中文注释会触发 `UnicodeDecodeError`；两个已提交的 `.txt` 锁文件同样只含 ASCII（uv 生成头 + 包名）。 |
| **`doctor.py` 在系统解释器下也报“环境就绪”** | 新增「解释器归属」检查：`sys.prefix` 必须等于 `<项目根>/.venv`，否则打印 `[FAIL]` 并以退出码 1 结束，同时给出正确命令；新增 `--allow-system` 仅供诊断系统解释器（只告警）。实测三组场景见 §3.3。 |

### 关于 `pip-compile --universal` 的偏差说明

任务书 T1.2 要求 `pip-compile --universal`，但实测 **pip-tools 7.6.2（PyPI 最新）没有 `--universal` 选项**（`pip-compile --help` 不含该开关，报 `No such option`）。为满足「跨平台锁文件」目标，改用 uv 0.9.2 的 `uv pip compile --universal --python-version 3.10` 生成；`scripts/lock-deps.*` 已封装该逻辑：**有 uv 用 uv，无 uv 退回 pip-compile 并明确警告“只能锁当前平台”**。已在 README「依赖锁文件维护」注明。

## 4. 环境问题与规避（记录）

1. **中文注释导致 pip 解码失败**：pip 按系统 locale 解码 requirements 文件，UTF-8 中文注释在 GBK 中文 Windows 上直接 `UnicodeDecodeError`。→ 所有 `.in` / `.txt` 依赖文件保持 ASCII。
2. **本机 pip 23.0.1 异常**：`pip install --upgrade pip`、`pip list`、以及无特殊参数的 `pip install -r` 会长时间卡住（CPU 空转，疑似沙箱下 pip 缓存/临时目录写入受限）。规避：`PIP_NO_CACHE_DIR=1`、`PIP_DISABLE_PIP_VERSION_CHECK=1`、`PIP_PROGRESS_BAR=off` 后正常；bootstrap 已加 `--disable-pip-version-check`，并在 README 记录该规避方式。**正常桌面环境通常不需要这些变量。**
3. **DSH 沙箱内 `%TEMP%` 不可写**：`win32com` 的 `gen_py` 缓存报 `PermissionError`，导致 WMI 导入失败；测试时用 `TEMP` 指向项目内 `.tmp` 规避。普通 PowerShell / 双击 `run.bat` 运行不受影响。
4. **pip-tools 无 `--universal`**：见 §2 偏差说明。
