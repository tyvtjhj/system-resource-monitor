| [scripts/doctor.py](../scripts/doctor.py) | T1.3 | 环境自检：Python 版本与解释器、关键依赖版本、当前平台、端口占用、`/api/start` 健康状态；仅用标准库，可在未装依赖的解释器上运行 |

依赖声明与任务书一致：

```toml
dependencies = [
  "flask>=3.0,<4",
  "psutil>=5.9,<8",
  "pynvml>=11.5,<14; sys_platform != 'darwin'",
  "WMI>=1.5.1,<2; sys_platform == 'win32'",
  "pywin32>=306; sys_platform == 'win32'",
]
```

`doctor.py` 的几个实现约定：

- **只依赖标准库**（`importlib.metadata` / `socket` / `urllib`），不 import flask/psutil，因此系统解释器也能运行并诊断缺包问题。
- **退出码**：`0` = 环境就绪；`1` = Python < 3.10 或缺少必需依赖。服务未运行、端口空闲**不算失败**（只是提示）。
- **必需/可选判定**：`flask`、`psutil` 全平台必需；`WMI`、`pywin32` 仅 Windows 必需；`pynvml` 可选（仅 NVIDIA 机器）。
- **编码**：输出到管道/文件时自动切 UTF-8，避免中文在 CI 日志或重定向文件里变成 GBK 乱码；交互式控制台保持默认编码（Windows 控制台直接写 Unicode）。
- 探测地址由 `MONITOR_HOST` / `MONITOR_PORT` 决定（`0.0.0.0` 自动折算为 `127.0.0.1`）；设置 `MONITOR_TOKEN` 时会带 `X-Monitor-Token` 请求 `/api/start`。

## 4. 环境问题与规避（重要）

1. **`requirements.txt` 中文注释导致 pip 失败**：UTF-8 中文注释在中文 Windows 的 GBK locale 下触发 `UnicodeDecodeError`。首个提交已把注释改为英文（pip 的 requirements 文件按 locale 解码，不认 UTF-8 无 BOM）。
2. **本机 pip 23.0.1 异常**：`pip install --upgrade pip` 会 CPU 空转卡死（约 10 分钟无进展），`pip list` 同样卡死。已规避：不升级 pip、不用 `pip list`（改用 `importlib.metadata` 核对版本）；安装依赖时显式指定 `--index-url https://pypi.org/simple`。
   - 影响：**本轮未生成 `requirements.txt` 锁文件**（需要 `pip-tools` 的 `pip-compile`，且同样依赖 pip 行为）。建议在可交互终端执行 `py -3.10 -m pip install pip-tools` 后运行 `pip-compile --universal requirements.in -o requirements.txt`；若 pip 仍异常，先手工修复 pip 环境（如用 `python -m ensurepip --upgrade` 或重装 pip）。
3. **DSH 沙箱内 `%TEMP%` 不可写**：`win32com` 的 `gen_py` 缓存会报 `PermissionError`，导致 WMI 导入失败。自检时已用工作区临时目录（`TEMP` 指向项目内 `.tmp`）验证通过；**用户在普通 PowerShell / 双击 `run.bat` 运行时不受影响**。`doctor.py` 只探测 HTTP，不依赖 WMI 缓存。
