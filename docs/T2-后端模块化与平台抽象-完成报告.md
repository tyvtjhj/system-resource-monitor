## 2. 平台抽象接口

两个平台模块都提供同名函数，由 `platform/__init__.py` 统一导出：

| 接口 | Windows | Linux |
|---|---|---|
| `is_elevated()` | `IsUserAnAdmin()` | `os.geteuid() == 0`（无 geteuid 时 False） |
| `request_elevation(argv)` | UAC `ShellExecuteW("runas")`，带 `--elevated` 防递归 | 始终 False（不调用 sudo） |
| `subprocess_flags()` | `{"creationflags": CREATE_NO_WINDOW}` | `{}` |
| `physical_disks()` | WMI `Win32_DiskDrive` | 遍历 `/sys/block`，排除 loop/ram/dm/sr/zram |
| `network_details()` | WMI `Win32_NetworkAdapterConfiguration` + psutil 按 MAC/IP 合并，失败回退纯 psutil | psutil + `/proc/net/route` + `/etc/resolv.conf` |

能力表语义：**表示平台支持什么，不代表设备一定存在**（设备缺失仍返回 `null`，前端显示 `--`）。

## 3. 第二轮评审修复（5 项）

| 评审问题 | 修复 | 验证 |
|---|---|---|
| **Major** `test_platform.py` 无条件断言 `linux_platform.physical_disks() == []`，真实 Ubuntu 上必然失败 | 改为跨平台条件断言：非 Linux 断言空列表；Linux 只断言返回列表与 `type/device` 字段；Linux 的真实逻辑改由「伪造 sysfs」用例覆盖 | 51 个测试在 Windows 全绿；Linux 上该用例不再假设空列表 |
| **Minor** Linux 缺「分区设备名映射到父设备」，整盘条目也没有 `device` 字段 | `physical_disks()` 增加 `"device": "/dev/<name>"`；新增并导出 `parent_device()`（`nvme0n1p1→nvme0n1`、`mmcblk0p1→mmcblk0`、`sda1→sda`，整盘返回 None），并作为平台接口 `partition_parent` 接入 `common.collect_disk()`：Linux 分区条目带 `parent_device`，Windows 返回 None 不改变原有结构 | 映射用例 + 假 sysfs 用例 + `collect_disk` 集成用例（附加/缺省/映射异常三种情况） |
| **Minor** macOS 上 `config.PLATFORM=other` 与 `capabilities.os=linux` 自相矛盾 | `platform/__init__.py` 的 `capabilities()` 统一用 `config.PLATFORM` 覆盖 `os` 字段；回退实现只负责其它能力项 | `test_capabilities_fields_and_os_consistency` + `test_capabilities_os_follows_config`（monkeypatch 为 other） |

## 4. API 变更（向后兼容）

| 接口 | 变化 |
|---|---|
| `GET /api/all` | 新增顶层 `platform` 字段：`{"os": "windows"/"linux", "capabilities": {...}}`；其余字段/状态码不变 |
| `GET /api/start` | 新增 `platform`（字符串）与 `capabilities`（对象）；原有 `status/ready/host/port/elevated` 不变 |
| 其它路由 | 无变化（`/api/<key>` 值缺失仍返回 503） |
