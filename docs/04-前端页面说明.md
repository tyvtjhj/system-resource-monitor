# 04 前端页面说明

前端是两个自包含的 HTML 文件：CSS、脚本全部内联，无框架、无打包、无外部 JS 依赖。唯一的远程资源是 Google Fonts（`DM Mono` + `Noto Sans SC`），离线时自动回退系统字体。

## 1. 两个页面的差异

| 能力 | [monitor-mobile.html](../monitor-mobile.html)（`/`） | [monitor.html](../monitor.html)（`/monitor.html`） |
|---|---|---|
| 定位 | 主页面，桌面 + 手机自适应 | 桌面版，布局相同 |
| CPU 核心侧栏 | 有 | 有 |
| 内存侧栏 | 有 | 有 |
| 硬盘侧栏 | 有 | 有 |
| 网络侧栏 | 有 | 有 |
| GPU 引擎侧栏 | 有，点击 GPU 卡片打开 | 无，GPU 卡片不可点击 |
| iGPU 卡片 | 有 | 有 |
| 温度卡片 | 有 | 有 |
| 主题切换 / 锚点 | 有 | 有 |
| 主要脚本行数 | 约 550-1375 行 | 约 527-1225 行 |

两页共用同一套后端接口；桌面版只是少了 GPU 侧栏相关函数与 DOM（`monitor.html` 中不存在 `gpuSidebar`、`openGpuSidebar`、`renderGpuSidebar`，也不使用 `gpu_engines` 字段）。

## 2. 页面结构

```text
body
└── .container
    ├── #errorState                连接失败提示 + 「重新连接」按钮
    ├── header
    │   ├── 标题 / Monitoring Active 状态点
    │   └── 主题按钮 #themeLabel / 时钟 #clock / 日期 #dateDisplay
    ├── .health-bar-container      OVERALL SYSTEM HEALTH + #overallFill
    ├── .sys-strip                 UPTIME / BOOT TIME / PROCESSES / THREADS
    ├── .grid-3（第一行）           CPU / MEMORY / DISK
    ├── .grid-3（第二行）           NETWORK / GPU / iGPU / TEMPERATURE
    └── aside 侧栏
        ├── #diskSidebar          物理硬盘 + 分区
        ├── #coreSidebar          总体负载 + 每核心历史
        ├── #memSidebar           进程内存排行（排序/口径切换）
        ├── #netSidebar           网卡 ipconfig 详情
        └── #gpuSidebar           GPU 型号 + 引擎利用率（仅主页面）
```

## 3. 主题与样式

### 3.1 主题变量

样式基于 CSS 变量（[monitor-mobile.html#L24-L64](../monitor-mobile.html#L24-L64)）：

- 基础色：`--bg`、`--card`、`--text-primary/secondary/tertiary`、`--border`
- 强调色：`--accent-blue/green/orange/red/purple`
- 语义色：`--track`、`--track-strong`、`--chip-good-bg/fg`、`--error-bg`

暗色模式仅覆盖 `html[data-theme="dark"]` 下的一组变量，因此卡片、仪表底环、进度条、徽标、侧栏会同时切换，无需逐组件写暗色样式。

### 3.2 防闪白

`<head>` 中有一段内联脚本（[monitor-mobile.html#L6-L17](../monitor-mobile.html#L6-L17)），在首次绘制前决定主题：

1. URL 有 `?theme=dark|light` → 强制该主题；
2. 否则读 `localStorage['monitor-theme']`；
3. 否则跟随系统 `prefers-color-scheme`。

运行时 `applyTheme()`（[L1338-L1346](../monitor-mobile.html#L1338-L1346)）会写回 `localStorage`，并更新按钮文案为「☀️ 亮色」/「🌙 暗色」。

### 3.3 响应式

断点：`1024px`、`900px`、`768px`、`600px`（侧栏宽度、网格列数、字号、内边距随之调整）。主容器最大宽度 1280px，手机端自动单列。

## 4. 脚本的组织方式

脚本位于 HTML 末尾，按功能分区，无模块系统。整体是「配置 → 通用工具 → 可视化组件 → 数据轮询 → 渲染 → 侧栏 → 主题 → 初始化」的线性结构。

| 区域 | 位置（主页面） | 说明 |
|---|---|---|
| 配置 | [L551-L563](../monitor-mobile.html#L551-L563) | `API_BASE`、`TOKEN`、`REFRESH_MS`、`connected`、`pollTimer` |
| API 封装 | [L558-L563](../monitor-mobile.html#L558-L563) | `apiFetch(path)` 附加 token 与 `no-store` |
| 安全写文本 | [L566-L570](../monitor-mobile.html#L566-L570) | `setText` 元素不存在时跳过，避免整轮刷新抛异常 |
| 时钟 | [L573-L577](../monitor-mobile.html#L573-L577) | 每秒更新 |
| Sparkline | [L580-L650](../monitor-mobile.html#L580-L650) | Canvas 多序列折线 |
| 仪表盘 | [L653-L701](../monitor-mobile.html#L653-L701) | SVG 圆环 |
| 轮询 | [L708-L730](../monitor-mobile.html#L708-L730) | `fetchAll` / `pollOnce` |
| 主渲染 | [L732-L892](../monitor-mobile.html#L732-L892) | `updateDashboard(data)` |
| 断线重连 | [L896-L898](../monitor-mobile.html#L896-L898) | `startService()` 仅重新拉取 |
| 侧栏 | [L903-L1192](../monitor-mobile.html#L903-L1192) | 五个侧栏的打开/关闭/渲染 |
| 侧栏数据渲染 | [L1193-L1335](../monitor-mobile.html#L1193-L1335) | 硬盘、核心历史 |
| 主题 | [L1337-L1346](../monitor-mobile.html#L1337-L1346) | 切换与持久化 |
| 初始化 | [L1348-L1374](../monitor-mobile.html#L1348-L1374) | 时钟、仪表、主题、首轮轮询、visibility、锚点 |

### 4.1 基础配置

```javascript
const API_BASE = `http://${location.hostname}:${location.port || 5678}`;
const TOKEN = new URLSearchParams(location.search).get('token') || '';
const REFRESH_MS = 2000;
```

- 用当前页面的主机名 + 端口推导 API 地址，因此手机通过 `http://<本机IP>:5678/` 打开时无需改代码。
- 页面必须由本服务提供（或同主机同端口），否则 API 地址可能不对。
- 协议固定为 `http://`；若通过 HTTPS 反向代理访问，会出现混合内容拦截，需要调整该行。
- `?token=` 只用于前端转发到 `X-Monitor-Token` 头。

### 4.2 轮询模型

```javascript
async function pollOnce() {
  clearTimeout(pollTimer);
  if (!document.hidden) await fetchAll();
  pollTimer = setTimeout(pollOnce, REFRESH_MS);
}
```

- **串行调度**：上一轮 `fetchAll` 完成后才启动 2 秒计时，避免请求叠加。
- **页面隐藏时暂停**：标签页不可见时跳过请求，但计时继续。
- **回到前台立即补一次**：`visibilitychange` 监听器调用 `fetchAll()`。
- 失败时显示 `#errorState`，并给出当前 `API_BASE`；点击「重新连接」只重新 `fetchAll()`，不会尝试启动服务。

`fetchAll` 只请求 `/api/all`。GPU 引擎、进程排行、网卡详情由侧栏按需请求：
- GPU 侧栏：打开时若没有引擎数据，请求 `/api/gpu-engines`，之后每 2 秒轮询。
- 内存侧栏：打开时请求 `/api/processes`，之后每 2 秒轮询；关闭即 `clearInterval`。
- 网络侧栏：打开时请求一次 `/api/network`（后端 5 秒缓存）。

### 4.3 `Sparkline` 类

[L580-L650](../monitor-mobile.html#L580-L650)：

| 特性 | 实现 |
|---|---|
| 多序列 | 构造时传颜色数组；`push(...values)` 按位置写入各序列 |
| 缺失值 | `Number.isFinite(value)` 不成立时存 `null`，绘制时跳过 |
| 共用纵轴 | 所有序列合并求 `min/max`，便于横向比较 CPU 与 GPU 温度 |
| 点数上限 | `maxPoints = 60`，超出后 `shift()` 丢弃最旧点 |
| 高清屏 | 画布宽高设为 CSS 尺寸的 2 倍，`setTransform(2,0,0,2,0,0)` |
| 绘制顺序 | 先画所有渐变面积，再画所有折线，避免面积遮挡相邻曲线 |
| 数据不足 | 有效点少于 2 个时直接返回，不绘制 |

实例：

- `netSL`：单序列蓝色，推入 `download_mbps`。
- `tempSL`：双序列 `['#3b82f6', '#ef4444']`，分别推入 CPU、GPU 温度。

### 4.4 圆形仪表

`createGauge(svgId, color)`（[L653-L678](../monitor-mobile.html#L653-L678)）动态创建四个 SVG 元素：

1. 背景圆：半径 `r + 8`，类 `gauge-bg`。
2. 前景圆：半径 `r = 85`，类 `gauge-fill`，`stroke` 预置为传入颜色，旋转 `-90deg` 从 12 点方向开始。
3. 数值文本：类 `gauge-value`。
4. 单位文本：`%`。

`setGauge(gauge, value)`（[L686-L696](../monitor-mobile.html#L686-L696)）：

```javascript
const v = Number.isFinite(value) ? Math.min(Math.max(value, 0), 100) : 0;
const fillLen = (v / 100) * (2 * Math.PI * gauge.r) + 2; // +2px 保证低值也可见
gauge.fill.style.strokeDasharray = `${fillLen}, ${fullCirc}`;
gauge.fill.style.stroke = v > 80 ? '#ef4444' : v > 60 ? '#f59e0b' : (gauge.color || '#3b82f6');
```

- 对 `NaN`、负数、超过 100 的值做钳制。
- 颜色阈值：>80% 红、>60% 橙、其余使用各卡片基色（CPU 蓝、内存紫、磁盘绿、GPU 红、核显青）。
- 返回对象包含 `color`，修复了历史上「占用 ≤60% 时整圈消失」的缺陷。
- `initGauges()` 在加载时先把五个仪表设为 0，保证首屏可见。

### 4.5 主渲染 `updateDashboard`

输入是 `/api/all` 的 JSON，按以下顺序更新：

| 区块 | 计算/取值 |
|---|---|
| 总体健康度 | 设计公式为 `100 - (cpu.usage×0.4 + memory.usage_percent×0.35 + 磁盘均值×0.25)`，结果钳制到 0-100；>60% 绿色，否则橙色。当前磁盘项因筛选条件问题实际未参与计算，见 [07 §3.1](07-设计决策与已知限制.md#31-总体健康度的磁盘权重实际未生效) |
| 系统信息条 | `system_info.uptime / boot_time / total_processes / thread_count`，用 `setText` 安全写入 |
| CPU | 仪表取 `usage`；徽标显示 `freq_current_mhz`；信息行显示占用、物理/逻辑核心数、频率；核心侧栏打开时同步重绘 |
| 内存 | 仪表取 `usage_percent`；徽标显示 `used_gb / total_gb` |
| 磁盘 | 只统计分区（`!d.type`），汇总 used/total 求百分比，仪表与徽标显示合计 |
| 网络 | `download_mbps` / `upload_mbps` 显示为 `MB/s`，并把下行值推入 `netSL` |
| GPU | 仪表取 `usage`；显示型号、占用、显存；缓存 `lastGpuData`，若 `/api/all` 带 `gpu_engines` 则一并缓存引擎数据 |
| iGPU | 有数据时显示型号、占用、共享内存；为 `null` 时显示「未检测到核显」 |
| 温度 | `temperature.sensors` 平均值作为徽标；优先用 `temperature.cpu/gpu`，缺失时按名字包含 `cpu`/`gpu` 兜底；`source` 映射为 `CPU PKG/OHM/ACPI/WMI`；悬停显示完整来源；CPU/GPU 两值推入 `tempSL` |

需要特殊说明的细节：

- 系统信息元素缺失不会中断刷新（`setText` 返回 `null` 也继续）。
- 温度标签颜色与曲线颜色一致：CPU 蓝、GPU 红。
- 磁盘健康度加权存在一处筛选条件问题，见 [07 设计决策与已知限制](07-设计决策与已知限制.md#3-代码阅读中发现的问题)。

### 4.6 侧栏实现

所有侧栏都是固定定位的 `aside.sidebar`，通过 `.active` 类滑入；`#sidebarOverlay` 负责半透明遮罩。

| 侧栏 | 打开 | 关闭 | 数据来源 | 刷新 |
|---|---|---|---|---|
| 硬盘 | `openDiskSidebar` [L903-L908](../monitor-mobile.html#L903-L908) | `closeDiskSidebar` [L910-L915](../monitor-mobile.html#L910-L915) | 复用 `lastDiskData`（来自 `/api/all`） | 随主轮询更新 |
| CPU 核心 | `openCoreSidebar` [L920-L925](../monitor-mobile.html#L920-L925) | `closeCoreSidebar` [L927-L932](../monitor-mobile.html#L927-L932) | 复用 `lastCpuData` | 主轮询时若打开则重绘 |
| 网络 | `openNetSidebar` [L944-L951](../monitor-mobile.html#L944-L951) | `closeNetSidebar` [L953-L959](../monitor-mobile.html#L953-L959) | `/api/network` | 打开时拉一次 |
| 内存 | `openMemSidebar` [L1004-L1010](../monitor-mobile.html#L1004-L1010) | `closeMemSidebar` [L1012-L1022](../monitor-mobile.html#L1012-L1022) | `/api/processes` | 打开时每 2 秒 |
| GPU | `openGpuSidebar` [L1092-L1129](../monitor-mobile.html#L1092-L1129) | `closeGpuSidebar` [L1131-L1141](../monitor-mobile.html#L1131-L1141) | 缓存 + `/api/gpu-engines` | 打开时每 2 秒 |

内存侧栏交互：

- `setMemSort('memory'|'name')`：按占用或名称排序。
- `setMemMetric('private'|'working')`：专用（USS，近似任务管理器）或工作集。
- 进度条按当前口径最大值归一化；占比 >10% 红、>5% 橙、其余绿。
- 同名进程合并为一行，`pids > 1` 时显示 `×N`。

GPU 侧栏交互：

- 引擎标签：`cuda → CUDA`、`3d → 3D`、`encode → 编码`、`decode → 解码`。
- 每项显示进度条，>80% 红、>60% 橙、其余绿。
- 数据优先复用 `/api/all` 中的 `gpu_engines`；为空时单独请求，并保持轮询。

核心侧栏：

- `renderCoreSidebar`（[L1229-L1283](../monitor-mobile.html#L1229-L1283)）为每个逻辑核心生成一个卡片，保存最近 30 个采样点。
- `drawCoreSparkline`（[L1284-L1335](../monitor-mobile.html#L1284-L1335)）按当前核心值着色：>80 红、>60 橙、其余蓝。

统一关闭：点击遮罩会依次调用五个 `closeXxxSidebar()`（[L935-L941](../monitor-mobile.html#L935-L941)）。

### 4.7 锚点直达

初始化时解析 `location.hash`（[L1357-L1374](../monitor-mobile.html#L1357-L1374)），支持：

| 锚点 | 侧栏 |
|---|---|
| `#memory` | 内存 |
| `#network` | 网络 |
| `#disk` | 硬盘 |
| `#cores` | CPU 核心 |
| `#gpu` | GPU（仅主页面） |

若对应数据尚未到达，会每 300ms 轮询等待，最多 10 秒。

## 5. 安全性说明

- 网卡与进程名称在插入 `innerHTML` 前做了 `& < > " '` 转义。
- 其他卡片（如 GPU 型号、CPU 温度来源）直接拼接后端字符串；数据来自本机，风险较低，但若未来接入不受信任来源，应统一转义。
- 页面无认证逻辑；token 只保护 API。不要将带 token 的 URL 分享给不受信任的人。

## 6. 修改前端时的注意事项

1. **两个页面同步**：新增卡片或公共逻辑时，`monitor-mobile.html` 与 `monitor.html` 需要同时修改；GPU 侧栏只存在于主页面。
2. **元素 ID 一致性**：`setText`/`getElementById` 依赖固定 ID；重命名要全局搜索。
3. **首屏**：仪表盘在 `initGauges()` 中预置 0，避免等待第一轮数据时空白。
4. **轮询不要改回 `setInterval`**：串行调度是避免请求堆积的关键。
5. **HTML 缓存**：服务端对页面设置 `no-cache`，修改后刷新即可生效；浏览器强缓存时可用 `Ctrl+F5`。
