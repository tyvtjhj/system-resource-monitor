# 07 设计决策与已知限制

本文记录代码中体现的关键取舍、降级策略、安全模型，以及阅读代码时发现的边界问题，便于后续维护。

## 1. 关键设计决策

| 决策 | 做法 | 原因 | 代价 |
|---|---|---|---|
| 快照式采集 | 后台线程写 `_state`，HTTP 只读 | 把 `sleep`、子进程、WMI 枚举移出请求路径，接口稳定在毫秒级 | 数据最多滞后一个采样周期；单指标接口不触发即时采集 |
| 单采样线程 | 所有指标在一个 `sampler_loop` 中按节奏执行 | 避免并发访问 WMI/PDH/NVML，逻辑简单 | 某个慢采集会推迟同轮后续指标；已用周期补偿与慢周期分流缓解 |
| 失败隔离 | `collect()` 捕获异常写 `<key>_error` | 单个传感器失败不应拖垮整块面板 | 失败时旧值保留，可能显示过期数据（见 §3） |
| 无前端框架 | 原生 HTML/CSS/JS，内联 | 无构建、单文件可分发、离线可用 | 两个页面存在重复代码，需要手工同步 |
| 多来源降级 | CPU 温度四级、网卡两级、核显多级识别 | Windows 没有统一用户态硬件接口 | 不同权限/机器上显示值与标签不同，需要向用户解释来源 |
| 默认自动提权 | 非管理员时 `ShellExecuteW("runas")` | 内核级 CPU 温度必须管理员 | 每次启动弹 UAC；提供 `--no-elevate` 与环境变量关闭 |
| 单实例检测 | 启动前请求 `/api/start` | Windows 允许重复绑端口，双实例会争抢响应 | 检测依赖端口与 token 配置；换端口可绕过 |
| 健康检查而非拉起进程 | `/api/start` 只回报状态 | 旧实现可被局域网触发拉起进程，属于安全漏洞 | 页面「重新连接」只能重试，不能远程启动服务 |
| 按需接口 + 短缓存 | `/api/processes` 1.5s、`/api/network` 5s | 进程枚举/WMI 查询较重，侧栏不需要 1 秒级刷新 | 数据可能有 1.5-5 秒延迟 |
| 同名进程合并 | 按进程名小写分组，累计 USS/工作集 | 与任务管理器展示方式一致，避免浏览器多进程拆成几十行 | 丢失单进程粒度；不同路径的同名程序会合并 |
| 核显用共享内存识别 | `GPU Adapter Memory` 中 Shared Usage 最大者 | 核显无独立显存，AMD/Intel 通用，不依赖厂商 SDK | 极端配置下可能误判；首次构建失败会永久禁用 |
| DLL 按字节加载 | `Assembly.Load(File.ReadAllBytes(...))` | 规避 `LoadFrom` 在可写目录的 `0x80131515` | 需要手动注册 `AssemblyResolve` 解析依赖 |
| 主题用语义变量 | `--track`、`--error-bg` 等集中覆盖 | 暗色模式只改一组变量即可作用到所有组件 | 新增组件需复用语义变量，避免写死颜色 |

## 2. 降级链

### 2.1 CPU 温度

```text
LHM 内核级（lhm，需管理员 + PawnIO）
  → OHM/LHM WMI 命名空间（ohm，对方程序需在运行）
  → ACPI 热区性能计数器（acpi，普通权限可用，平台温度偏低）
  → Win32_TemperatureSensor（wmi，多数机器为空）
  → null，页面显示 --
```

页面标签映射：`lhm → CPU PKG`、`ohm → CPU OHM`、`acpi → CPU ACPI`、`wmi → CPU WMI`。

### 2.2 网卡详情

```text
WMI Win32_NetworkAdapterConfiguration（含网关/DNS/DHCP）
  + psutil（友好名称/速率/MTU，按 MAC 或 IP 关联）
  → WMI 不可用：纯 psutil（无网关/DNS，dhcp=null）
```

### 2.3 磁盘

```text
WMI Win32_DiskDrive（物理盘型号/接口/序列号）
  + psutil.disk_partitions(all=True)（分区用量）
  → WMI 失败：仅分区；无介质/无权限分区跳过
```

### 2.4 GPU

```text
NVIDIA：NVML 提供利用率/显存/温度
        + nvidia-smi dmon 提供引擎（-q 兜底）
核显：  GPU Adapter Memory 识别适配器
        + GPU Engine 计数器汇总 3D/Compute/VideoDecode/VideoEncode
        + WMI/注册表取型号
```

## 3. 代码阅读中发现的问题

以下为静态阅读结论，**未修改代码**，供后续维护参考。

### 3.1 总体健康度的磁盘权重实际未生效

两个页面的 `updateDashboard` 都有：

```javascript
const validDisks = (data.disk || []).filter(d => d.type != null && !isNaN(d.usage_percent));
```

但后端返回的两种元素互斥：

- 分区对象**没有** `type` 字段 → `d.type != null` 为 `false`，被排除；
- 物理盘对象有 `type="physical"`，但**没有** `usage_percent` → `isNaN(undefined)` 为 `true`，被排除。

结果 `validDisks` 恒为空，`overallLoad` 只包含 CPU（0.4）与内存（0.35）加权，磁盘的 0.25 权重从未参与。总体健康度因此偏高。

若需修复，可改为只筛选分区：`filter(d => !d.type && Number.isFinite(d.usage_percent))`，并同步修改两个 HTML。

相关位置：[monitor-mobile.html#L738-L742](../monitor-mobile.html#L738-L742)、[monitor.html#L709-L713](../monitor.html#L709-L713)。

### 3.2 采集异常时旧值保留

`collect()` 在异常分支只调用 `put_error`，不清除已有的指标值。因此：

- `/api/all`：可能同时出现旧值与 `<key>_error`；
- `/api/<key>`：`_metric` 看到值非 `None`，返回 200 与旧值，错误信息不会暴露。

如果希望失败时明确返回 503，需要在异常分支把值置为 `None`（并考虑是否会误伤短暂抖动）。当前行为相当于「最后一次已知值」，对看板是合理取舍，但排障时需注意。

### 3.3 核显首次构建失败后不再重试

`GpuPerfReader.sample()` 在首次 `_build()` 或导入 `win32pdh` 失败时设置 `self._unavailable = True`，之后直接返回 `None`（[server.py#L508-L521](../server.py#L508-L521)）。若服务启动过早、GPU 计数器尚未就绪，本次进程生命周期内 iGPU 都不会恢复，需要重启服务。

### 3.4 首轮温度可能短暂显示 ACPI

`CpuTemperature.read()` 首次调用时，LHM 子进程可能尚未产出第一条 JSON，`_from_lhm()` 返回 `None`，链路继续落到 ACPI 并缓存 3 秒。随后 LHM 数据到达，下一轮才会切换为 `CPU PKG`。因此启动后短时间内看到 `CPU ACPI` 属正常现象。

### 3.5 网络速率的单位命名

后端字段名为 `download_mbps` / `upload_mbps`，但实际计算是 `bytes / 1024² / 秒`，即 MiB/s；前端标签写作 `MB/s`。数值本身正确，只是命名与标签在严格意义上应为 MiB/s。另外 `psutil.net_io_counters()` 默认汇总所有网卡，可能包含本机回环流量。

### 3.6 GPU 温度只取第一块卡

`collect_temperature` 中 `gpu_entry` 只在遍历 NVML 传感器时取第一个（`if gpu_entry is None`），多卡机器上 `temperature.gpu` 只代表第一块 GPU；`sensors` 里仍保留所有卡的条目。

### 3.7 页面协议固定为 HTTP

前端 `API_BASE` 写死 `http://`，并拼接 `location.hostname` 与 `location.port`。若通过 HTTPS 反向代理访问页面，浏览器会拦截混合内容请求；需要改脚本或加同源相对路径。

### 3.8 桌面版缺少 GPU 引擎侧栏

`monitor.html` 没有 `gpuSidebar` 相关 DOM 与函数，GPU 卡片也不可点击；但后端仍会为它计算 `gpu_engines`（通过 `/api/all` 返回），属于轻微冗余。

### 3.9 其他小观察

- `monitor_already_running()` 只认 HTTP 200 且响应含 `"status"`，若端口上运行的是恰好返回类似内容的其他服务，可能误判；概率很低。
- WMI 线程内连接不主动释放，进程退出时由系统回收。
- `collect_disk` 使用 `psutil.disk_partitions(all=True)`，会包含系统保留分区；无权限或无介质的分区被跳过。
- 页面部分位置直接拼接后端字符串到 `innerHTML`（如 GPU 型号、温度来源），数据源是本机，风险有限；新增外部数据源时应统一转义。
- 仓库没有自动化测试、构建流程或 CI；验证依赖手工启动与页面观察。

## 4. 已知限制

| 限制 | 说明 | 规避方式 |
|---|---|---|
| Windows 专属能力 | WMI、PDH、PawnIO、`nvidia-smi` 均面向 Windows | 在其他系统上仅 psutil 相关指标可用 |
| CPU 核心温度需要管理员 | 读 MSR 依赖内核驱动 | 用 `run.bat`/`run-admin.bat` 提权；否则接受 ACPI 平台温度 |
| PawnIO 可能被拦截 | HVCI、易受攻击驱动黑名单、版本不匹配都会导致读数为空 | 安装/更新 PawnIO；或改用 HWiNFO 共享内存方案（需扩展） |
| 只有 NVIDIA 有完整 GPU 指标 | NVML 与 `nvidia-smi` 只支持 NVIDIA | AMD/Intel 独显只能显示型号；核显走 PDH |
| 核显依赖英文性能计数器 | 非英文 Windows 上对象名可能不同 | 需按语言环境适配计数器名称 |
| WMI 受限账号失败 | 沙箱/受限账号可能「拒绝访问」 | 使用普通桌面账号；物理盘列表可能为空 |
| 进程状态不准确 | Windows 上 psutil 通常把存活进程都报为 RUNNING | 「运行中进程数」≈「进程总数」 |
| 无历史持久化 | 只有内存快照与页面上的短曲线 | 需要历史数据时自行接入时序数据库 |
| 局域网默认可访问 | 默认 `0.0.0.0:5678`，同网段可见硬件与进程名 | 设置 `MONITOR_HOST=127.0.0.1`，或启用 `MONITOR_TOKEN` |
| token 不加密传输 | HTTP 明文，token 可被同网段嗅探 | 仅在可信网络使用；需要加密时前置 HTTPS 反向代理 |
| 字体依赖外网 | Google Fonts 不可达时回退系统字体 | 离线部署可删除字体 `<link>` |

## 5. 安全模型

1. **默认提权**：服务通常以管理员运行，但只读取硬件信息，不修改系统设置。
2. **API 可选鉴权**：`MONITOR_TOKEN` 为空时局域网内任何人可读取全部指标；这是默认配置，需要时务必设置。
3. **页面不受保护**：token 只拦 `/api/*`；页面本身可被访问，但没有数据。
4. **只读接口**：所有 API 均为 GET；历史漏洞「通过 `/api/start` 拉起进程」已移除，现为健康检查。
5. **CORS 默认放开**：`MONITOR_CORS_ORIGIN=*` 允许任意网页读取 API（若浏览器能访问该地址），可通过环境变量收紧。
6. **子进程参数**：PowerShell 与 `nvidia-smi` 均以固定参数列表执行，不拼接用户输入，无命令注入面。
7. **依赖来源**：`vendor/lhm` 为官方签名二进制，`NOTICE.txt` 记录了版本与 SHA-256；升级时应核对来源。
