## 3. 快照与错误隔离

```python
def put(key, value):
    with _state_lock:
        _state.pop(key + "_error", None)
        _state[key] = value

def put_error(key, err):
    with _state_lock:
        _state[key + "_error"] = str(err)

def collect(key, fn, *args):
    try:
        value = fn(*args)
    except Exception as exc:
        put_error(key, exc)
        print(f"[WARN] collect {key} failed: {exc}")
        return None
    put(key, value)
    return value
```

行为说明：

- 一个采集器抛异常时，只记录 `<key>_error`，**不会**中断整轮采样。
- 采集器返回 `None` 不算异常，`put` 会把 `None` 写入快照；`/api/<key>` 因此返回 503，`/api/all` 中该字段为 `null`。
- 失败时旧值不会被清除：如果 `collect` 抛异常，快照里仍是上一轮的值，同时出现 `<key>_error`。`/api/all` 能同时看到旧值与错误标记，`/api/<key>` 则仍返回旧值。
- `_snapshot()` 会过滤所有以下划线开头的键（如 `_cycle_ms`），再写入 `latency_ms`。

### 4.6 温度：`LhmReader` + `CpuTemperature`

#### `LhmReader`（[L756-L866](../server.py#L756-L866)）

负责以子进程方式运行 [lhm_temp.ps1](../lhm_temp.ps1)：

| 成员 | 说明 |
|---|---|
| `find_dll()` | 依次查找 `MONITOR_LHM_DLL` → `vendor/lhm/LibreHardwareMonitorLib.dll` → FanControl（x86/x64）→ LibreHardwareMonitor 安装目录 |
| `start()` | 拼接 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File lhm_temp.ps1 -DllPath ... -IntervalMs ...`，`CREATE_NO_WINDOW` 隐藏窗口，启动 `_pump` 线程 |
| `_pump()` | 逐行读取 stdout，`json.loads` 后写入 `_state` / `_state_at` |
| `read()` | 返回最近一条结果；超过 `max_age`（默认 10s）视为失效 |
| `exited()` | 子进程是否已退出 |
| `stop()` | 终止子进程 |

`lhm_temp.ps1` 的关键点：

- 先以 **字节方式** `Assembly.Load(File.ReadAllBytes(...))` 加载 DLL，并注册 `AssemblyResolve` 解析同目录依赖，规避 `LoadFrom` 的 `0x80131515` 错误。
- 把 `C:\Program Files\PawnIO` 加入 `PATH`，否则 LHM 找不到 `PawnIOLib.dll`，读数为空。
- 传感器优先级：`CPU Package` → `Core Max` → `Core Average`。
- 连续 3 轮读不到值时输出 `{"ok": false, "error": ...}` 并退出，避免无意义轮询。

#### `CpuTemperature`（[L868-L1056](../server.py#L868-L1056)）

按顺序尝试四种来源，命中即返回：

| 顺序 | 方法 | 来源标识 | 权限要求 | 特点 |
|---|---|---|---|---|
| 1 | `_from_lhm()` | `lhm` | 管理员 + PawnIO | 真正的 `CPU Package`，与 FanControl/HWiNFO 一致 |
| 2 | `_from_monitor_wmi()` | `ohm` | 取决于对方程序 | 若 OHM/LHM 正在运行，查 `root\LibreHardwareMonitor` / `root\OpenHardwareMonitor` |
| 3 | `_from_acpi_counter()` | `acpi` | 普通用户 | `Thermal Zone Information` 计数器，开尔文转摄氏，取最热区域 |
| 4 | `_from_wmi_sensor()` | `wmi` | 视机器 | `Win32_TemperatureSensor`，多数机器为空 |

返回结构统一为 `{"name": "CPU (...)", "value": 41.2, "source": "lhm"}`。

节流与重试逻辑（`read()`，[L1044-L1056](../server.py#L1044-L1056)）：

- 有缓存且未超过 3 秒 → 直接返回缓存。
- 无值时不缓存，下一轮继续尝试。
- ACPI 枚举失败或没有计数器时，60 秒后才重试，避免每轮浪费约 200ms。
- LHM 启动失败、子进程退出或明确回报 `ok=false` 时，`_lhm_disabled=True`，本进程生命周期内不再尝试。
- OHM WMI 与 `Win32_TemperatureSensor` 各自只检查一次。

`collect_temperature(nvml, cpu_reader)`（[L1059-L1072](../server.py#L1059-L1072)）把 NVML 的 GPU 传感器与 CPU 结果合并：

```json
{
  "sensors": {"GPU (NVIDIA ...)": 52.0, "CPU (CPU Package)": 61.0},
  "cpu": {"name": "CPU (CPU Package)", "value": 61.0, "source": "lhm"},
  "gpu": {"name": "GPU (NVIDIA ...)", "value": 52.0}
}
```

### 4.7 进程与网卡详情（按需计算）

这两项不进入后台采样，只在侧栏请求时计算，并带短缓存。

#### 进程内存排行

`collect_processes(limit=40)`（[L603-L658](../server.py#L603-L658)）：

1. 遍历 `psutil.process_iter(["pid", "name"])`，读取 `memory_info()` 与 `memory_full_info().uss`。
2. `uss` 失败时退回 `memory.private`。
3. 按 **进程名小写** 合并同名进程，累计 `private_mb`（专用，近似任务管理器「内存」列）与 `working_set_mb`（工作集）。
4. 计算占物理内存百分比，按 `private_mb` 降序，取前 `limit` 条。

缓存：`_process_cache` + `_process_lock`，TTL 1.5 秒（[L596-L600](../server.py#L596-L600)）。

#### 网卡详情

`collect_network_detail()`（[L667-L752](../server.py#L667-L752)）：

1. 从 psutil 建立两个索引：`by_mac`（MAC 去掉分隔符并大写）与 `by_ip`（IPv4）。
2. 优先遍历 WMI `Win32_NetworkAdapterConfiguration(IPEnabled=True)`，取 IP、掩码、网关、DNS、DHCP、MAC、描述。
3. 用 MAC 关联 psutil 的友好连接名、链路速率、MTU；关联不到再用 IP 匹配。
4. WMI 不可用或结果为空时，退回纯 psutil 结果（无网关/DNS）。
5. 排序规则：`up=True` 在前，其次按名称字母序。

`_normalize_mac()`（[L662-L664](../server.py#L662-L664)）统一 WMI 的 `:` 与 psutil 的 `-` 写法。

缓存：`_network_cache` + `_network_lock`，TTL 5 秒（[L599-L600](../server.py#L599-L600)）。

## 5. 采样调度：`sampler_loop`

[L1154-L1216](../server.py#L1154-L1216)：

```text
初始化 NvmlSession / CpuTemperature / GpuPerfReader
记录上一轮网络计数器与时间戳
预热 cpu_percent

while not _stop.is_set():
    cycle_started = now
    采集 cpu、memory
    计算 network_speed（差分）
    采集 gpu（拿 gpu_name 供引擎结果复用）
    采集 temperature
    if 到达慢周期:
        disk、system_info、igpu
    if 到达引擎周期:
        nvidia-smi 引擎数据，并与本轮 gpu 信息合并为 gpu_engines
    写入 _cycle_ms
    等待 max(0.05, 1.0 - 本轮耗时)
```

设计细节：

- 慢周期与引擎周期用 `next_slow` / `next_engine` 时间戳推进，而不是取模计数，避免周期漂移。
- `gpu_engines` 合并了顶层 `name`、`mem_used_gb`、`mem_total_gb` 以及嵌套 `gpu`，前端两种取法都兼容。
- 采样循环整体包在 `try/except` 中，任何未预期异常只打印警告并等待 1 秒，线程不会死亡。

## 8. 扩展新指标的步骤

以新增「风扇转速」为例：

1. **写采集函数**：`def collect_fan(): ...`，返回可 JSON 序列化的结构；可能失败的操作自行捕获或交给 `collect`。
2. **挂到采样循环**：在 `sampler_loop` 的合适位置调用 `collect("fan", collect_fan)`；重操作放进 `if cycle_started >= next_slow` 分支。
3. **加单指标路由**（可选）：`@app.route("/api/fan")` → `_metric("fan")`。
4. **前端渲染**：在 `updateDashboard` 中读取 `data.fan`；新卡片需要同步修改两个 HTML 文件。
5. **更新文档**：本文的采集函数表、[03 接口参考](03-HTTP接口参考.md) 与 [01 架构总览](01-架构总览.md) 的快照键表。

注意事项：

- 新采集器不要在 Flask 请求线程中执行阻塞操作；需要按需计算时参考 `/api/processes` 的缓存模式。
- 新增字段不要以 `_` 开头，否则会被 `_snapshot()` 过滤。
- 需要管理员权限的采集逻辑要提供降级路径，避免普通权限下整轮失败。
