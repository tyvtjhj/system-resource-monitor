# 开发执行任务书：可复制环境、跨平台与插件化

> 交付对象：负责编码的 agent。
>
> 执行方式：按 T1 → T6 顺序实施。每个任务完成后先自测，再进入下一个任务；T5 可在 T4 完成后并行。
>
> 核心约束：不破坏现有 Windows 功能和 URL；不引入数据库；不修改 `vendor/lhm` 二进制；不把 token 放进 iframe URL；不承诺向 VS Code/Trae/Cursor 的内置聊天 DOM 注入内容。

## 1. 项目基线

当前仓库是单进程 Windows 硬件看板：

- [server.py](../server.py)：约 1460 行，配置、采集、Flask 路由、启动流程全部集中在一个文件。
- [monitor-mobile.html](../monitor-mobile.html)：主页面，5 个侧栏，手机自适应。
- [monitor.html](../monitor.html)：桌面版，无 GPU 引擎侧栏。
- [lhm_temp.ps1](../lhm_temp.ps1)：Windows PowerShell 子进程，读取 CPU 内核温度。
- [vendor/lhm](../vendor/lhm)：LibreHardwareMonitorLib 0.9.6 及依赖。
- [requirements.txt](../requirements.txt)：仅 `>=` 下限，无锁文件。
- 无 `pyproject.toml`、无 `.venv`、无测试、无插件目录、无 `.gitignore`。

平台耦合点：

| 功能 | server.py 位置 | 平台依赖 |
|---|---|---|
| 管理员检测 / UAC | L36-82 | `ctypes.windll.shell32` |
| WMI | L216-234 | `pythoncom`、`wmi` |
| 物理硬盘 | L241-280 | `Win32_DiskDrive` |
| 核显 / GPU 引擎 | L317-592 | `win32pdh`、注册表 |
| 网卡详情 | L667-727 | `Win32_NetworkAdapterConfiguration` |
| LHM 子进程 | L756-865 | PowerShell、`CREATE_NO_WINDOW` |
| CPU 温度链 | L868-1056 | OHM/LHM WMI、`Thermal Zone Information` |
| 启动 | L1390-1456 | UAC、Windows 端口行为 |

跨平台可复用：`put/put_error/collect`（L91-111）、CPU/内存/网络速率（L115-147）、分区/进程/系统信息（L264-313、L603-658）、NVML（L151-212）、Flask 鉴权/CORS/页面服务（L1220-1281）。

### T1 可复制运行环境（Must）

**T1.2 依赖声明与锁文件**

`pyproject.toml` 使用以下内容为基准：

```toml
[project]
name = "hardware-monitor"
version = "2.0.0"
description = "Local hardware monitor with Flask and a zero-build dashboard"
requires-python = ">=3.10"

  "flask>=3.0,<4",

[project.optional-dependencies]
dev = ["pytest>=8", "pytest-cov>=5", "ruff>=0.6", "pip-tools>=7"]

[build-system]

[tool.pytest.ini_options]
```

- `requirements.in` 复制 `[project].dependencies` 的直接依赖（不带 dev extras）。
- `requirements-dev.in` 包含 `-r requirements.in` 加 `pytest`、`pytest-cov`、`ruff`、`pip-tools`。
- `requirements.txt` 用 `pip-compile --universal requirements.in -o requirements.txt` 生成并提交；`requirements-dev.txt` 同理。
- 锁文件必须保留平台 marker：Linux 不安装 `WMI`/`pywin32`。

**T1.3 初始化与自检脚本**

- `scripts/bootstrap.ps1`：依次尝试 `py -3.10`、`py -3`、`python`；校验版本 `>=3.10`；创建 `.venv`；升级 pip；安装 `-r requirements.txt`；打印激活命令。失败时给出明确退出码。
- `scripts/bootstrap.sh`：依次尝试 `python3.10`、`python3`；其余同上。
- `scripts/lock-deps.ps1` / `.sh`：运行 `pip-compile --universal`，并生成 dev 锁文件。
- `scripts/doctor.py`：输出 Python 版本、已安装关键包版本、当前平台、端口 5678 占用情况；若服务在运行，请求 `/api/start` 并打印状态。

**T1.4 启动脚本**

- `run.bat`：若 `.venv\Scripts\python.exe` 存在则使用它启动 `server.py`；否则回退 `py -3.10`，再回退 `python`；透传 `%*`。
- `run-admin.bat`：保留现有提权逻辑，但提权后优先使用 `.venv\Scripts\python.exe`，不存在时回退 `py -3.10`。
- `run.sh`：若 `.venv/bin/python` 存在则使用它，否则回退 `python3`；透传 `"$@"`。

**T1.5 文档**

- `README.md` 增加：环境初始化、Windows/Linux 启动、依赖锁文件维护、插件接入入口。
- `使用说明.txt` 增加：虚拟环境安装步骤、Linux 启动、插件安装简述。
- 保留原有 `py -3.10 server.py` 用法说明。

**T2.4 Linux 平台模块**

新增 `hardware_monitor/platform/linux.py`：

- `is_elevated()`：`os.geteuid() == 0`；`request_elevation()` 始终返回 `False`，启动日志提示不自动提权。
- CPU 温度：
  1. `psutil.sensors_temperatures()`，优先 `Package id 0`、`Tctl`、`Tdie`、`Core 0`，来源 `hwmon`；
  2. 回退 `/sys/class/thermal/thermal_zone*/temp`，读取 `type` 与 `temp`（毫摄氏度），优先 `x86_pkg_temp`、`cpu`、`soc`，来源 `thermal`；
  3. 都没有返回 `None`。
- 物理盘：遍历 `/sys/block/*`，排除 `loop*`、`ram*`、`dm-*`、`sr*`、`zram*`；读取 `device/model`、`device/serial`、`size`（512 字节扇区）、`queue/rotational`；分区设备名映射到父设备（`nvme0n1p1` → `nvme0n1`，`sda1` → `sda`）。
- 网卡详情：psutil 提供名称/MAC/IPv4/IPv6/掩码/速率/MTU/up；网关解析 `/proc/net/route`；DNS 解析 `/etc/resolv.conf`；`dhcp` 无法判断时为 `None`。
- 核显：AMD 读取 `/sys/class/drm/card*/device/gpu_busy_percent`、`mem_info_vram_used`、`mem_info_vram_total`，温度读 `hwmon/hwmon*/temp1_input`；Intel 本期返回 `None`；无数据返回 `None`。
- `capabilities()` 返回 Linux 能力表。

**T2.5 采样调度与 API**

- `hardware_monitor/sampler.py`：保留原节奏（快 1s、慢 3s、引擎 3s），从平台模块取采集器；异常只打印警告，线程不退出；保留 `_cycle_ms`。

- `create_app()` 不启动采样线程，便于测试；采样线程只在 `__main__.py` 启动。

**T2.6 测试**

- `tests/conftest.py`：构造测试用 Flask app，注入固定快照，避免真实采样。
- `tests/test_state.py`：`put` 清除错误、`collect` 失败隔离、快照过滤。
- `tests/test_api.py`：`/api/all`、单指标 200/503、token 401、CORS 头、页面 200。
- `tests/test_collectors.py`：`net_speed` 差分、`_parse_dmon` 列顺序、`_parse_query` 兜底、`_normalize_mac`。
- `tests/test_platform.py`：当前平台能力表字段完整，Windows/Linux 分支可导入。

### T4 通用插件与缩略组件（Should）

**T4.1 后端路由与响应头**

在 `hardware_monitor/api.py` 新增：

| 路由 | 文件 | 说明 |
|---|---|---|
| `GET /plugin` | `plugin/plugin.html` | 集成中心 |
| `GET /widget` | `plugin/widget.html` | 缩略页 |
| `GET /embed.js` | `plugin/embed.js` | 宿主注入脚本 |
| `GET /api/plugin/manifest` | 动态 JSON | 插件元数据 |

`/api/plugin/manifest` 返回：

```json
{
  "name": "hardware-monitor",
  "version": "2.0.0",
  "api_version": 1,
  "base_url": "http://127.0.0.1:5678",
  "widget_url": "/widget",
  "dashboard_url": "/",
  "auth": {"type": "token", "header": "X-Monitor-Token"},
  "platform": {"os": "windows", "capabilities": {}}
}
```

响应头：

- 所有 HTML：`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`、`Cache-Control: no-cache`。
- 完整页面：`Content-Security-Policy: frame-ancestors 'self'`。
- `/widget`：`Content-Security-Policy: frame-ancestors <MONITOR_FRAME_ANCESTORS>`，默认：
  ```text
  'self' http://127.0.0.1:* http://localhost:*
  ```
- `/embed.js`：`Content-Type: application/javascript; charset=utf-8`。
- 不使用 `X-Frame-Options`。

**T4.3 宿主注入脚本**

新增 `plugin/embed.js`：

- 解析 `<script>` 的 `data-target`、`data-position`、`data-theme`、`data-base-url`、`data-token`、`data-collapsed`。

- 通过 iframe 加载 `/widget?embed=1`，执行 `postMessage` 握手：
  1. iframe → 宿主：`monitor:ready`；

  4. iframe → 宿主：`monitor:state`。
- 校验 `event.source === iframe.contentWindow`，并校验 `event.origin` 属于允许列表。
- **iframe URL 不携带 token**；token 只通过握手传递。
- 暴露 `window.HardwareMonitor.mount(options)`、`unmount()`、`toggle()`。

**T4.4 集成中心页面**

**T4.5 测试**

## 5. 关键实现约束

1. **Windows 优先**：T2 迁移后先跑 Windows 全量对比，再处理 Linux；Windows 回归未修复前不要继续 T4。
2. **保持 API 兼容**：不重命名现有字段；`/api/all`、`/api/<key>` 的状态码语义保持不变。
3. **异常隔离**：新采集器失败只写 `<key>_error`，不得让采样线程退出；缺失数据用 `None`。
4. **不自动提权 Linux**：Linux 只报告权限状态，不调用 `sudo`。
5. **Token 安全**：嵌入场景只用 `postMessage` 传递 token；`Referrer-Policy: no-referrer`；不把 token 写入 iframe URL。
6. **嵌入安全**：`/widget` 使用 `frame-ancestors` 白名单，默认仅本机；外部宿主显式配置 `MONITOR_FRAME_ANCESTORS`。
7. **不夸大能力**：VS Code/Trae/Cursor 不承诺注入内置聊天 DOM；提供侧边栏/面板/状态栏。
8. **无新重依赖**：后端不引入 Web 框架/数据库；插件核心纯 JS，无构建即可运行；VS Code 扩展的 Node 工具链仅用于可选适配器。
9. **保留兼容入口**：`python server.py`、`run.bat`、现有页面路径继续可用。
10. **不要修改** `vendor/lhm` 二进制和 `lhm_temp.ps1` 的加载方式，除非为跨平台兼容必须调整，并在文档中说明。

## 6. 默认决策（无需再询问）

| 问题 | 默认决策 |
|---|---|
| Python 基线 | 3.10，兼容 3.11/3.12；bootstrap 找不到 3.10 时允许更高版本并提示 |
